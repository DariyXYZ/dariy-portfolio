# Портфолио продуктового дизайнера

Сайт-портфолио Дария Назарова: витрина кейсов, страница о себе, резюме.
Прототип с черновым наполнением — дизайн и архитектура готовы, контент
наполняется постепенно.

## Требования

- Node.js 20+
- npm 10+

## Установка и запуск

```bash
npm install
npm run dev        # http://localhost:3000
```

## Команды

```bash
npm run dev        # разработка
npm run build      # production-сборка
npm run start      # запуск собранного приложения
npm run lint       # ESLint
npm run typecheck  # tsc --noEmit
```

## Переменные окружения

Смотри `.env.example`. Сейчас нужен только публичный адрес для метаданных
и Open Graph.

## Архитектура воронки

Сайт устроен как последовательность для рекрутера, а не как галерея работ.
Каждый экран отвечает на следующий вопрос читателя.

| Шаг | Секция | Что должен вынести читатель | Время |
|---|---|---|---|
| Хук | Первый экран | Кто я и чем отличаюсь | 5 сек |
| Доверие | Полоса фактов | Опыт, отрасли, цифры | 20 сек |
| Интерес | Витрина кейсов | Что изменилось в продуктах | 2 мин |
| Глубина | Страница кейса | Как я принимаю решения | 10 мин |
| Личность | Обо мне | С кем предстоит работать | 2 мин |
| Действие | Контакт | Как написать | всегда доступно |

Приёмы, работающие на конверсию:

- **В заголовке карточки — результат, а не название проекта.** Рекрутер
  сканирует итоги, а не бренды.
- **Резюме PDF в шапке и футере.** Первое, что ищет рекрутер, не должно
  требовать поиска.
- **Статус доступности отдельной плашкой.** Снимает главный вопрос до
  переписки.
- **Фильтр кейсов по отрасли.** Помогает быстро найти релевантное.
- **Кейсы в работе показаны, но без ссылки.** Объём работы виден, обещаний нет.
- **Сквозной переход к следующему кейсу.** Читатель не возвращается в список.

## Структура

```
src/
├── app/                 маршруты и сборка страниц
│   ├── _components/     блоки только для главной
│   ├── work/            витрина кейсов и страница кейса
│   └── about/           страница о себе
├── components/
│   ├── ui/              кнопки, плашки, секции, рамка макета, анимация появления
│   └── layout/          шапка и подвал
├── features/
│   ├── cases/           данные кейсов, типы, карточка
│   └── profile/         опыт, образование, навыки, процесс
└── config/              настройки сайта и навигация
```

Направление зависимостей: `app → features → components / lib`.

## Дизайн-система

Токены лежат в `src/app/globals.css`, компоненты — в `src/components/ui`.

- **Палитра.** Тёплые нейтральные: чернильный `#1B1A18`, песочный `#F7F6F3`,
  белый. Единственный семантический цвет — зелёный статуса доступности.
  Контрасты проверены: основной текст 6.4:1, подписи 4.6:1.
- **Типографика.** Onest для всего, JetBrains Mono для номеров и лейблов.
  Крупные заголовки набраны обычным начертанием с плотным трекингом
  (`-0.038em`) — приём даёт спокойный, не рекламный тон.
- **Форма.** Волосяные границы вместо теней, радиусы 10/16/22 и пилюли.
- **Движение.** Каскадное появление первого экрана и `IntersectionObserver`
  для секций. Одна кривая `cubic-bezier(0.16, 1, 0.3, 1)`, длительности
  180/420/720 мс. `prefers-reduced-motion` отключает всё.

## Отличия от стандарта бюро

- Тестов пока нет: проект на стадии прототипа, критической логики почти нет.
  Появятся вместе с фильтрами и формой обратной связи.
- Вместо Tailwind используются CSS Modules и слой токенов: типографика и ритм
  задаются один раз и не размазываются по классам в разметке.
